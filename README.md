# SciGap — выявление научных проблем в публикациях

**Локальный эксперимент: Single-Agent Qwen vs Multi-Agent Qwen → Phi → Qwen → Gemma**

SciGap извлекает из научных PDF исследовательские проблемы — **пробелы в знаниях, методах, данных или инструментах, на устранение которых направлена публикация**. Цель статьи, полученный результат, общий фон темы и ограничения авторского эксперимента сами по себе не считаются такими проблемами.

Проект позволяет сравнить два режима **на одном и том же исходном списке Qwen**:

- **Single-Agent:** первоначальный результат Qwen после автоматической проверки подтверждающих цитат.
- **Multi-Agent:** Phi критикует первоначальный список, Qwen защищает/исправляет его, Gemma принимает или отклоняет кандидатов. До трёх раундов обсуждения.

## 1. Состав проекта

```text
SciGap/
├── README.md              # эта инструкция
├── requirements.txt       # зависимости Python
├── settings.py            # модели и параметры эксперимента
├── prompts.py             # системные инструкции и запросы моделям
├── prepare.py             # извлечение текста PDF, страницы и фрагменты
├── ollama_api.py          # общение с Ollama, повторы запросов, телеметрия
├── agents.py              # логика Qwen / Phi / Qwen / Gemma
├── run.py                 # парный запуск эксперимента
├── evaluate.py            # предварительное сравнение и ручная оценка
├── visualize.py           # создание HTML-отчёта
├── data/
│   ├── gold.json          # человеческая эталонная разметка
│   └── pdfs/              # научные публикации
└── output/                # появляется при первом запуске
    ├── processed/         # подготовленный текст публикаций
    └── <имя_серии>/
        ├── single/        # JSON результатов Single-Agent
        ├── multi/         # JSON результатов Multi-Agent
        ├── telemetry.jsonl
        ├── environment.json
        ├── experiment.log
        ├── report.html
        ├── evaluation_auto/      # только при автоматическом сравнении
        ├── review.csv            # шаблон проверки, если создан evaluate.py
        └── evaluation_reviewed/  # после ручной оценки
```

В поставляемом архиве **30 PDF: 20 англоязычных и 10 русскоязычных**.

Эталон `data/gold.json` содержит **30 записей и 96 проблем**

## 2. Требования

Эксперимент ориентирован на **Windows 11**, **8 ГБ VRAM**, **32 ГБ RAM**, локальный **Ollama** и **Python 3.11** (рекомендуется; совместимость других версий зависит от установленных библиотек).

Нужны:

1. Установленный Python, доступный командой `python`.
2. Установленный и запущенный [Ollama](https://ollama.com/).
3. Достаточное свободное пространство для PDF, моделей и промежуточных JSON.
4. Драйвер NVIDIA для ускорения на видеокарте; `nvidia-smi` желателен для мониторинга, но не обязателен для базового запуска.

В PowerShell перейдите в каталог распакованного проекта:

```powershell
cd "C:\path\to\SciGap"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Если PowerShell запрещает запуск скрипта активации, можно выполнять команды через `.\.venv\Scripts\python.exe` вместо `python` без активации окружения.

## 3. Установка локальных моделей

Откройте PowerShell:

```powershell
ollama pull qwen3.5:4b
ollama pull phi4-mini:3.8b-q4_K_M
ollama pull gemma4:e4b-it-q4_K_M
ollama pull bge-m3
ollama list
```

`bge-m3` нужна **только для необязательного семантического сопоставления с человеческим эталоном**, а не для извлечения проблем и не для создания основного HTML-отчёта. Если служба Ollama не работает, запустите приложение Ollama (или `ollama serve`, если это соответствует вашей установке).

Проверьте подключение и наличие трёх основных моделей:

```powershell
python run.py --check
```

При успехе программа перечислит модели со статусом `OK` и завершится без обращения к PDF и без запуска извлечения.

## 4. Как устроена обработка статьи

```text
PDF
 │
 ├─ prepare.py: текст страниц → фрагменты с перекрытием
 │
 └─ Qwen 3.5 4B: кандидаты + страницы + цитаты
       │
       ├─ программная сверка цитат с текстом PDF
       ├─ объединение, устранение текстовых дублей, ограничение до 7 проблем
       │
       ├───────────────────────────┐
       ▼                           ▼
   Single-Agent                 Multi-Agent
   (сохраняется)                  │
                            Phi: замечания
                                  ↓
                            Qwen: защита,
                            keep/rewrite/remove
                                  ↓
                            Gemma: арбитраж,
                            принять/отклонить
                                  ↓
                         до 3 раундов обсуждения
                                  ↓
                            итоговый JSON
       └───────────────────────────┘
                      ↓
                visualize.py
                      ↓
                  report.html
```

Обе конфигурации используют **один начальный список**. Повторный вызов Qwen в триаде — это защита первоначальных проблем, **не новое независимое извлечение из PDF**.

Типовые настройки из `settings.py`:

| Параметр | Значение |
|---|---:|
| Длина фрагмента PDF | 5 500 символов |
| Перекрытие фрагментов | 350 символов |
| Кандидатов на фрагмент | до 3 |
| Проблем в окончательном списке одной статьи | до 7 |
| Контекст Qwen и Phi | 6 144 токена |
| Контекст Gemma | 4 096 токенов |
| Максимум раундов обсуждения | 3 |
| Условие досрочной остановки | оценка раунда ≥ 8/10 и выполнены дополнительные проверки решений |
| Температура генерации | 0 (основная настройка) |

Контекстные окна — **инженерные настройки для оборудования с 8 ГБ VRAM**, а не экспериментально доказанные оптимумы. Дополнительно ограничивается длина генерируемых ответов, в зависимости от роли модели.

Автоматическая сверка цитат проверяет, найдена ли цитата в извлечённом тексте PDF, но **не устанавливает научную правильность формулировки**. Сканированные PDF без текстового слоя могут потребовать отдельного OCR: данная программа не гарантирует распознавание изображений страниц.

## 5. Быстрый запуск: две статьи

При необходимости отдельно подготовьте текст первых двух PDF:

```powershell
python prepare.py --limit 2
```

Предварительная подготовка **не обязательна**: `run.py` самостоятельно читает и кэширует PDF.

Пробный запуск (1 экспериментальный повтор):

```powershell
python run.py --name pilot --limit 2 --repeats 1
```

После окончания откройте:

```powershell
start .\output\pilot\report.html
```

Если HTML автоматически не сформировался, выполните:

```powershell
python visualize.py --name pilot
```

Основной HTML можно построить **без модели `bge-m3`**. При отсутствии модели embeddings автоматический этап семантического сравнения может выдать предупреждение, но это не препятствует генерации отчёта из сохранённых JSON.

## 6. Полный запуск и обработка партиями

**29 статей, по одному повтору:**

```powershell
python run.py --name corpus29 --repeats 1
```

**29 статей, по три экспериментальных повтора:**

```powershell
python run.py --name corpus29 --repeats 3
```

**Партиями по пять статей (одна серия, одинаковые условия):**

```powershell
python run.py --name corpus29_batch --start 0  --limit 5 --repeats 1
python run.py --name corpus29_batch --start 5  --limit 5 --repeats 1
python run.py --name corpus29_batch --start 10 --limit 5 --repeats 1
python run.py --name corpus29_batch --start 15 --limit 5 --repeats 1
python run.py --name corpus29_batch --start 20 --limit 5 --repeats 1
python run.py --name corpus29_batch --start 25 --limit 4 --repeats 1
```

Запуск одной статьи по части имени файла:

```powershell
python run.py --name one_paper_new --paper 2603.28304 --repeats 1
```

`--start` отсчитывается **с нуля** в отсортированном списке активных PDF. `--name` определяет каталог серии `output/<имя>`. Не смешивайте под одним именем результаты с разными моделями, промптами, корпусом или экспериментальными настройками.

Если оба JSON одной статьи и повтора уже сохранены, повторный запуск той же серии с теми же настройками пропустит их. Если Single уже готов, а Multi ещё нет, программа использует сохранённый Single.

### «Три повтора» и «повторные запросы» — разные вещи

- `--repeats 3` — **три отдельных экспериментальных прогона** статьи для оценки устойчивости результатов.
- Параметр `retries` в `settings.py` — **технические повторные попытки** запросов Ollama из-за ошибки сети, HTTP или некорректного JSON. Они не являются отдельными экспериментальными прогонами.

## 7. Только обновить HTML, без повторной работы моделей

Для уже существующей серии, например `corpus30`, достаточно:

```powershell
python visualize.py --name corpus30
start .\output\corpus30\report.html
```

**Число принятых проблем** берётся из финальных `problems` в JSON триады, а не задаётся вручную. Эти значения показывают действия системы, а не экспертную правильность проблем.

## 8. Человеческая разметка и оценка качества

Файл `data/gold.json` содержит эталонные формулировки (`statement`), их идентификаторы (`id`) и подтверждающие выдержки (`evidence.quote`). Часть полей `page` может быть `null`: это означает, что номер страницы не указан в эталоне, а не что проблема неправильная.

Система поддерживает два **предварительных автоматических** метода сопоставления формулировок с эталоном:

- `semantic` — косинусная близость векторов локальной многоязычной модели `bge-m3`;
- `lexical` — сходство символьных n-грамм TF-IDF.

Их результаты **не являются подтверждением TP/FP**. Порог сопоставления — техническая эвристика, не метрика истинности научной проблемы. Автоматические результаты сохраняются отдельно в `evaluation_auto` и не предъявляются в главном HTML как доказанное качество.

При необходимости создать автоматические сопоставления и **шаблон ручной проверки**:

```powershell
python evaluate.py --name corpus30 --matcher semantic
```

Для лексического baseline (без `bge-m3`):

```powershell
python evaluate.py --name corpus30 --matcher lexical
```

В `output/corpus29` вручную заполните по **каждому предложению модели**:

- `reviewed_status`: `TP`, `FP`, `Partial`, `Duplicate` или `NONE`;
- `gold_id`: идентификатор человеческого эталона при `TP`, `Partial` и `Duplicate` (при `FP`/`NONE` оставить пустым);
- `comment`: пояснение эксперта, когда полезно.

`TP` означает корректную проблему, сопоставленную конкретному эталону данной статьи. Для одного режима и одного повтора **один gold_id нельзя засчитать как TP дважды**. `Partial` и `Duplicate` отдельно фиксируются, но **не входят в строгие TP**. `NONE` используется для статьи, у которой список предсказаний пуст. Не удаляйте строки из шаблона, иначе проверка полноты завершится ошибкой.

Затем:

```powershell
python evaluate.py --name corpus30 --review .\output\corpus30\review.csv
```

Ручные метрики **Precision, Recall и F1** будут сохранены в `output/corpus29`. Отдельно рекомендуется просматривать **правильные проблемы, ошибочно отклонённые триадой**, и **ложные проблемы, корректно устранённые триадой**. Без такой проверки нельзя утверждать, что Multi-Agent точнее Single-Agent.

## 9. Где искать результаты

| Файл / папка | Назначение |
|---|---|
| `output/<серия>/single/*.json` | Проблемы Qwen и исходные подтверждения |
| `output/<серия>/multi/*.json` | Проблемы триады, раунды, критика/защита/арбитраж |
| `output/<серия>/report.html` | Интерактивный отчёт |
| `output/<серия>/experiment.log` | Ход работы и ошибки |
| `output/<серия>/telemetry.jsonl` | Запросы моделей и технические показатели |
| `output/<серия>/environment.json` | Модели, настройки, хеши исходных файлов и кода |
| `output/<серия>/errors.jsonl` | Ошибки обработки, если они возникли |
| `output/<серия>/review.csv` | Шаблон экспертной проверки |
| `output/<серия>/evaluation_auto/` | Диагностические автоматические сопоставления |
| `output/<серия>/evaluation_reviewed/` | Метрики по ручной экспертной проверке |

Не редактируйте JSON результатов моделей ради улучшения статистики: это нарушает воспроизводимость. При необходимости исправления фиксируйте версию кода и условия запуска.

## 10. Типичные проблемы

| Ситуация | Что проверить / сделать |
|---|---|
| `Ollama недоступна` | Запущена ли служба; совпадает ли `OLLAMA_URL` в `settings.py` с `http://127.0.0.1:11434`. |
| Отсутствует модель | Выполнить соответствующий `ollama pull` и `python run.py --check`. |
| HTTP 500, `token repeat limit reached`, невалидный JSON | Скрипт предусматривает технические повторы запросов; проверить `experiment.log`, VRAM и размер контекста. Не путать с `--repeats`. |
| Пустой или испорченный текст PDF | Проверить извлечение текста через `prepare.py`; сканированные документы могут нуждаться в OCR. |
| Серия не продолжает обработку из-за SHA-256 / настроек | Для нового опыта использовать **новое имя `--name`**. Не смешивать результаты разных конфигураций. |
| Нет `bge-m3` | Для HTML она не нужна. Для semantic-оценки скачать `ollama pull bge-m3` или использовать `--matcher lexical`. |
| HTML старый после исправления `visualize.py` | Выполнить `python visualize.py --name <серия>` и обновить страницу в браузере. |
| Ручная оценка выдаёт ошибку | Проверить полный набор строк `review.csv`, допустимые статусы, уникальные `prediction_id`, корректные `gold_id`. |

### Важное предупреждение после очистки `gold.json`

`run.py` сохраняет в `environment.json` SHA-256 файла человеческого эталона. Удаление служебных полей из `gold.json` **меняет SHA-256**, даже если формулировки и цитаты остались прежними. Поэтому **новую обработку моделей** с очищенным файлом запускайте под **новым именем серии**. Для простого пересоздания HTML по существующим JSON это не требуется.

`--resume-after-fix` не предназначен для обхода изменения эталонного SHA-256: код помечает некоторые параметры как неизменяемые и может отказать в продолжении старой серии. Нельзя выдавать неоднородные серии за единый контролируемый эксперимент.

---

**Рекомендуемый порядок работы:** `ollama pull` → `pip install` → `run.py --check` → `run.py --name ...` → `visualize.py` → при необходимости `evaluate.py` и ручная проверка.
